Factory Inventory Management System

Architecture overview: system components, technology stack, and data flow

System Architecture

A demo full-stack application. A Vue 3 single-page app talks to a FastAPI service over HTTP/JSON. The API serves data that is loaded from JSON files into memory at startup. There is no database.

Data Flow

Every page follows the same request cycle when a filter changes:

  1. The user changes a filter in FilterBar.vue: Time Period, Warehouse, Category, or Order Status.
  2. The view's filter state in composables/useFilters.js updates, and a watcher triggers a reload.
  3. The view calls one or more methods on api.js. Each method builds a query string and omits any value set to all.
  4. FastAPI validates the query parameters and runs the matching filter helpers (apply_filters, filter_by_month) on copies of the in-memory data.
  5. The response is validated against a Pydantic model and returned as JSON.
  6. The view stores the raw data in refs (for example allOrders, inventoryItems). Derived values are computed properties, and the template renders them.

Known Gaps

Missing routes  client/src/api.js calls /api/tasks (get, create, delete, toggle) and /api/purchase-orders (create, get by backlog item). server/main.py defines neither, so those calls return 404. App.vue calls getTasks() on load.
Hardcoded URL  The API base URL is set to http://localhost:8001/api in api.js, which ties the client to a local backend.
Mock auth  composables/useAuth.js returns a fixed demo user. There is no login.
Open CORS  The server allows all origins. This is fine for local development only.
No persistence  Writes do not persist, and a restart reloads the JSON files.
